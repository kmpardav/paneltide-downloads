PanelTide Creator's Guide

From first imported pages to considered editorial changes and recoverable work

16 October 2026 | Windows preview 0.11.0
PanelTide 0.11.0 Windows preview; Photoshop development panel 0.5.0

Use your browser's Find command to search this guide. Choose a chapter in Contents or open the printable PDF. This standalone guide starts no application, model or network request.

1. Start here

PanelTide is an editorial companion for comic creators. It helps you supply the right material, examine recommendations and choose a useful next step. It does not replace the artist, publish a comic, certify professional quality or decide that an intentional choice is wrong.

Edition: this guide describes PanelTide 0.11.0, a Windows x64 preview released on 16 October 2026, with the optional Photoshop development panel 0.5.0. It is unsigned and has no commercial service. Independent creator acceptance and signing are not part of this release.

Read the Quick start if you are new. Read the professional workflow if you already have a drawing, lettering or production process. Buttons are named as they appear in 0.11.0. If your app differs, check its actual version and release notes before following a newer workflow.

There is no ideal panel count imposed on every page. More context can clarify pacing, transitions and voice, but only supplied material that is actually included in the selected review can support a conclusion. An empty result is not a publication pass.

2. Quick start: your first considered change

  1. Open Your comics. Check the current comic name before adding anything.
  2. Create a named empty comic, or use the original schematic sample as a separate comic in Page studio. Keep your existing work.
  3. For your own comic, export PNG pages from Photoshop or Clip Studio Paint. Choose PNG pages, inspect order/names/previews and Add pages to this comic. Import stays local.
  4. Open Review workspace. Write what the scene should communicate. Save story context and relevant Page script & scene notes.
  5. Choose One page or With neighbouring pages. Prepare page review saves a local frozen request; no model is called yet.
  6. Open Connections. If you want automatic AI, complete the separate sample check for a configured route. Read its destination and usage disclosure.
  7. Return to the prepared review, choose an available route and Analyze these pages. This explicit click can share the selected previews/notes and consume provider usage.
  8. Compare each observation with the supplied page. Read sources, uncertainty, alternatives and tradeoffs. Keep intentional choices; make only useful advice into tasks.
  9. Edit a separate candidate in your drawing app. Retain the native original. Re-export and import the actual changed PNG as additional material; changed-page replacement is not automatic.
  10. Prepare a fresh review of the revision. A task marked complete is your declaration, not evidence that a model or host verified the improvement.

If you do not want to configure AI yet, importing, story notes, schematic planning, viewing saved findings, tasks, original-page exchange and backups remain local. A manual review pack is an optional fallback, not a required beginner procedure.

3. Download, install and open

The current download is PanelTide 0.11.0 for Windows x64, available as setup and portable. It is unsigned; publisher identity is not certified by a signing certificate. No account is required to use the local preview.

  1. For setup, launch the downloaded installer and choose an installation folder. Installation is per Windows user.
  2. For portable, launch the downloaded portable executable. Portable refers to how the program starts; its workspace is still stored in this Windows user's application-data folder.
  3. Open the app. The normal entry point is Review workspace. Choose Your comics for your library.
  4. If another PanelTide window is already running, use that window. The application uses one owned local service.
  5. If the service port is occupied by another application, read the error and close only a service you recognize. PanelTide does not kill unrelated processes.

This guide is not an installer. Earlier releases have their own guides and feature boundaries. Automatic updates are not active.

Narrow installed evidence covers one Windows user and OS, including a normal 0.8 to 0.9 update. This is not certification of every Windows version, machine, display, installer path or upgrade failure. Installing 0.11.0 over 0.10 or 0.9 keeps the workspace folder; make a backup in Backup and recovery before any update. Automatic updates are not active.

Application files normally install under %LOCALAPPDATA%\Programs\PanelTide. Workspace data is separate under %APPDATA%\PanelTide\workspace. File > Open workspace data folder opens the actual folder. Moving an executable does not move the workspace or AI access.

5. Create and open a comic

  1. In Your comics, expand Create a new comic.
  2. Enter Comic name. Choose Print comic left to right, Print comic right to left, or Vertical scroll.
  3. Optionally describe the audience, mood or story effect. You can refine this later.
  4. Choose Create comic. A separate empty comic is added; the current saved comic is not overwritten.
  5. Select an existing library card to open that comic. Confirm its title before importing pages or preparing a review.

The current library supports up to 10 comics and 30 pages per comic. Repeated page names in different comics do not establish shared identity. Reviews and tasks are associated with a stable comic identity, so another comic cannot inherit authority merely by using the same page IDs.

Open a PanelTide project file imports a source-only copy as a new identity. It does not restore the original comic's review/task history, AI authentication or Photoshop pairing. Import is not a full workspace restore.

Before Open, Refresh or a library action, finish the pending import/new-comic work or keep an inspectable copy. A different comic name is not a merge target. Comic identity, original files, review history and native approvals are separate.

6. Manage copies, Archive and Trash

  1. In Your comics, find the saved comic and choose Manage. The action operates on saved work, not unapplied Studio changes.
  2. For an alternate edition, choose Save a copy. Enter Copy name and Preview. Read the named source/new comic and history exclusions.
  3. Choose Save this copy to create and open a new identity. Saved pages/context/credits/original PNG references are retained. Prior reviews/tasks/approvals remain with the source. Export a story file separately if you need its narrative catalog.
  4. For Archive or Move to Trash, Preview the action. If this is the current comic, select another available comic to open instead. At least one comic must remain available.
  5. Confirm only the named action. Neither Archive nor Trash deletes source files, history or recovery copies.
  6. To return a retained comic, Manage it in the relevant section, choose Restore to Your comics, Preview, then Restore this comic. Restoring does not automatically change the current comic.

The ten-comic limit includes Archive and Trash. Permanent deletion, automatic purge and a final retention policy are not implemented. A source-only copy is not a copy of all review/task history.

A change in another window invalidates the preview. Make a fresh preview after checking the current saved version. If the response is interrupted, Check saved result inspects the exact attempted action. It does not send the write again. If the result stays unconfirmed, retain the earlier work and refresh/read before another action.

7. Import PNG pages

  1. Export flattened pages as PNG from Photoshop or Clip Studio Paint. Keep your editable PSD or .clip originals in your drawing workflow.
  2. In Your comics, check the name under Import into your current comic.
  3. Choose PNG pages. You may select multiple pages; review the preview list before adding them.
  4. Rename pages if needed and use the available order controls. Filename order alone is not reliable story order.
  5. Choose Add pages to this comic. This commits the confirmed batch locally.
  6. Open Review workspace. Imported pages are flattened references; physical panels, balloons and text have not been detected.

PanelTide retains the exact PNG file it accepts, including bytes and a hash. A separate smaller preview is made for inspection/review. Its color, transparency or print metadata can differ. Downloading a rendered page preview does not recover a print master. Download the retained source from Your comics when you need the imported PNG.

If your source exceeds a limit, export a separate review copy from the drawing app and keep the master there. Label that copy in your source notes. PanelTide cannot retain a larger rejected master by silently calling the resized copy the original.

Cancel page import stops before the add step. Discard this import removes the pending preview batch; it does not delete already saved comic pages. If validation or saving fails, read the message and retry a corrected batch; an HTTP success, a pending preview or a canceled file dialog is not proof that pages were committed.

8. Keep source credits and permissions visible

  1. While preparing PNG pages, expand Source credits for this import. Choose Add a source-credit record when attribution is needed.
  2. Record the source title, creator, source URL, licence, licence URL, attribution and a useful rights note as available. Keep unknown facts unknown.
  3. Incomplete fields remain pending text. Checked HTTPS links and bounded records are validated when you explicitly add the pages.
  4. Review Supplied source credits in Your comics and the selected-page export manifest. Use the original licence terms when deciding whether sharing is permitted.

These are creator-supplied records. Recording a URL, owning a subscription, downloading an image or passing a checksum does not establish legal clearance. PanelTide does not fetch a referenced image, negotiate rights or certify permission. No external upload follows from adding credits.

A PNG source can preserve metadata bytes while still being flattened. Credits do not restore editable layers, the native file or printer approval. Keep PSD/PSB/.clip masters and source licence documents separately.

9. Recover unfinished PNG and project-file work

  1. Wait for the pending copy to be confirmed locally. Retry saving pending copy is for the current unfinished data; it is not the final Add/Create/Open action.
  2. Choose Refresh earlier copies, select one and Preview pending copy. Inspect the comic, page names/order, received originals, missing files, incomplete previews and raw credit fields.
  3. Choose Continue PNG preparation if the originals are retained and previews are unfinished. Choose the project file again when its exact input bytes are missing.
  4. Choose Compare with saved comic before rescuing older work. Read each exact saved match, changed saved page, unfinished original or not-saved item.
  5. Recover unresolved pages skips exact saved matches and gives changed earlier pages fresh pending identities. Recover all as additional pages retains the entire selected group, including deliberate duplicates.
  6. Check the new pending batch and credits. Add pages to this comic is still required; recovery itself adds nothing. For a checked project file, Open checked project creates the source-only new copy explicitly.

Current pending work and unapplied Studio edits must be kept before adopting an earlier copy. Recovery publishes a separate writer; old/current copies remain. New typing while recovery finishes stays visible. If the exact result is uncertain, use Check recovery outcome rather than repeating publication.

Cancel preparation stops unfinished processing. Discard this import clears that window's pending batch, not saved pages. Missing originals are not silently reconstructed from a smaller preview. Earlier incomplete New fields can be recovered in Your comics; recovery starts a fresh creation attempt instead of reopening/replacing the older saved comic.

Full cross-comic editing merge, repair/retention management and every crash/power-loss/large-file case remain open. Keep inspectable originals and confirmed copies; do not delete internal files to force recovery.

10. Explain the story and scene

Write what you want readers to understand or feel, rather than asking AI to enforce generic best practices. For example: 'Mara speaks STOP; Elias stays silent. Keep the dry mood. The door reveal should surprise us without making the action unclear.' This gives the review an explicit target and lets it distinguish a creator-rule conflict from a creative option.

  1. Open Story context and edit the intended effect.
  2. Save story context before preparing a review. Unsaved notes are not automatically the review's saved context.
  3. Select a page and expand Page script & scene notes.
  4. Describe what is visible, who speaks, the intended beat and any relevant off-screen information.
  5. Save page context. These notes guide the review; they do not change drawing-app layers or pixels.
  6. Choose whether to Include character notes in the new review. Exclude notes that are irrelevant or private.

Character and scene notes can explain voice, continuity and intent. The separate Script and story bible workspace can index a whole saved text source, but page-review requests do not implicitly include that script or its approved rules. Use the sharing summary to see exactly what was supplied.

Page layout tells reviews how readers meet your pages: printed pages that face each other, a vertical scroll strip, or one page at a time on screen. It also records the reading direction and, for print, whether page 1 stands alone facing the inside cover or pages 1 and 2 open together as a spread. Until you set it, reviews assume nothing about facing pages or page turns.

  1. In the Review workspace, open Set page layout below the comic title.
  2. Choose how readers see the pages, the reading direction and, for print, how page 1 starts. The description under the choices says how the pages pair up.
  3. Choose Save page layout. The page list then shows each page's side and whether it comes after a page turn or faces another page.
  4. To go back to no assumption, choose Change page layout and then Clear page layout. Existing reviews keep the layout they were made with.

Changing title, format, intent, page layout, included character notes or page material can make a prepared review stale. Prepare fresh context after such changes. Saved historical findings remain attached to the earlier snapshot.

11. Import, edit and keep original scripts

  1. Open Script and story bible for the current saved comic. Confirm its name and supplied artwork count.
  2. Choose a UTF-8 TXT or Markdown file, or enter Script filename and Script text. PDF/DOCX/OCR/screenplay format import is not supported here.
  3. Import creates an immutable application version with exact original bytes, filename and SHA-256. Save new version creates another version; earlier originals remain unchanged.
  4. Use Original files and Download original to retrieve any saved version byte-for-byte, including its original UTF-8 BOM/newlines.
  5. Read the source index. Explicit SCENE, PAGE and PANEL labels and paragraphs are located by source lines/byte ranges. A PANEL label is a script beat, not detected artwork geometry.
  6. Compare saved script when pending editor text differs. Keep the pending text or explicitly replace the editor; another saved version is not silently adopted.

A simple supported example is SCENE doorway: confrontation, then PAGE 1, PANEL a, MARA: Stop. and a paragraph describing Elias. Labels use a number up to four digits or an ASCII identifier up to 32 characters. SCENE: DOOR is not a recognized scene declaration in parser v 1. Markdown heading markers can precede labels; fenced content stays text. The parser does not infer story meaning, chronology or speakers.

Text typing during Save remains dirty if it is newer than the version being saved. An interrupted save is checked by its exact mutation result, not by assuming that any version increment was your write. Do not alter hashes or version identifiers to force acceptance.

The saved index is local, not an AI read or quality judgment. Current page analysis does not include the script automatically. Full-script and script-plus-pages provider workflows, cross-version beat reconciliation and scene-graph synthesis remain additional implementation.

12. Map beats and understand coverage

  1. At a source beat choose Map this beat. Choose a state, artwork page and a confirmed physical panel where appropriate.
  2. Add a reason for Intentional difference. Check the current script version/artwork and Save mapping.
  3. Read the map status after artwork changes. Artwork changed since mapping means its earlier declaration no longer matches the saved target.
  4. Use page-level mapping when physical panel geometry is unknown. Do not treat a whole-page reference container as a detected panel.
  5. Check coverage separately: Indexed means a block was located. Reviewed/Failed needs a matching trusted review receipt; indexing alone does not count as review.

More pages can supply transitions and recurring details; a whole script can supply distant setups and intended voice. Neither proves unseen visual staging, lettering fit, composition or emotional acting. Only a review explicitly receiving that material may reason about it. No whole-issue quality/coverage percentage is inferred.

13. Approve your story bible and style rules

  1. In Story bible & style rules, enter a title, category and rule text. Categories cover character/costume/prop/location/chronology/spelling/palette/style/reference definitions.
  2. Choose Whole comic, a uniquely declared scene, a supplied page or a confirmed panel. Add optional reference URL and rights/attribution note.
  3. Save proposal. A proposed rule is not yet approved canon.
  4. Read it and choose Approve rule with an optional decision note only when its scope is available.
  5. Edit proposal creates a new proposed revision and retains the earlier decision. Retire rule ends its current use; retirement is not a deletion of history.
  6. Export saved story for a separate .paneltide-story file. Import story file appends new source/rule identities, makes rules proposals and keeps imported map declarations inactive until checked.

An approved definition with a missing/ambiguous scope is not effective. References are recorded data, not fetched images or cleared licences. A canon decision is creator context, not authority to run a host command or upload material.

Portable .paneltide comic files and .paneltide-story files are separate. Story export contains original versions/definitions/declarations, excluding approvals, review receipts, artwork target hashes, authentication, mutation receipts and execution rights. Work backups can preserve the supported local catalog; a library Save a copy does not automatically clone its narrative sidecar.

14. Recover raw script editor text

  1. Wait for the editor copy to be confirmed locally; each window has a separate writer. Saved script versions and pending text remain distinct.
  2. Choose Check earlier editor copies, select one and Preview pending text. Inspect the full raw filename/text, including empty incomplete fields.
  3. Recover into a separate editor copy first confirms the current input and rechecks source/current/destination. Earlier copies remain; no saved script version is created.
  4. Review the adopted filename/text and any stale-base warning. Correct an invalid filename without discarding the text, then Save new version explicitly.
  5. Retry keeping current text retries the current draft checkpoint, not an uncertain saved-script mutation. Use the saved-outcome check when a write response is unknown.

Recovery does not approve canon, restore host authority, mark source blocks reviewed or send the script to AI. A newer saved source, changed target, failed storage or newer typing can prevent adoption. Confirmed copies remain inspectable. Recovering an old editor cannot bypass current script-version/comic checks.

Unfinished story-bible proposals, beat-mapping inputs and rule-decision notes are kept the same way, per window, under Proposal, mapping and decision recovery in Script and story bible and in Collection story. Partial values such as an incomplete reference link are kept as typed; nothing is fetched or approved.

  1. Choose Check earlier form copies, then select an earlier copy in the list.
  2. Choose Preview pending forms and read every kept field before deciding.
  3. Choose Recover forms into a separate editor. Your current inputs are confirmed first and stay protected; the recovered values appear in their own editor copy.
  4. If a copy belongs to another comic, choose Return to these inputs’ original comic instead of moving the text across comics. If keeping inputs failed, choose Retry keeping my form inputs.

Recovering forms never saves a proposal, approves canon, maps a beat or sends anything to AI. Save each proposal, mapping or decision yourself after checking it.

A page plus its neighbour may resolve a deliberately unexplained object or identify who is addressed. It may also introduce more irrelevant information. Start with the smallest useful scope and add context for a concrete question. More pages do not automatically mean better advice.

For print, set the page layout (chapter 10). Reviews of neighbouring pages then know which pages share a spread and where the reader turns the page. For vertical scroll, describe the viewport and scroll rhythm in your notes; the layout records only that the pages form one strip. Without a page layout, 'With neighbouring pages' does not establish a physical page turn.

Imported pages have unknown physical panel geometry until you mark panels in Page studio. Until then the app may show a whole-page reference container. Treat a nullable/page-wide target as honest uncertainty, not as a detected panel. OCR and automatic panel detection are future work.

In this edition: a new page or neighbouring-page review records its original focus. Custom selected-page reviews have no primary focus. Viewing a different page in the review gallery does not change the original focus. Older reviews say that the original focus was not recorded; PanelTide does not guess it from image order.

16. Prepare, inspect sharing and analyze

  1. Choose the focus page and scope. Review the included character-note choice.
  2. Choose Prepare page review. This saves a frozen local snapshot; it does not call a model.
  3. Read the page/context and AI-route sharing summary. Confirm these are the materials you intend to send.
  4. Choose Analyze these pages only when the route is verified and you accept the stated cloud sharing.
  5. Wait for the result or choose Cancel review. PanelTide does not automatically retry an interrupted request.
  6. When received, read Recommendations alongside their supplied pages. No artwork is automatically edited.

Preparing a new snapshot captures its selected notes and preview pixels at that time. Subsequent source changes do not rewrite that historical evidence. A changed project may reject analysis or result acceptance; prepare a fresh review rather than forcing old feedback onto new work.

Automatic routes can include verified ChatGPT via Codex and separately configured API/local adapters after their own sample check. Choose the exact available route shown in the app. Configured, reachable or advertised does not mean verified. No tool is installed, model downloaded or cloud allowance inferred from a model catalog.

Cancel prevents local acceptance when it can do so. It does not refund provider usage, undo a remote request or prove that cloud work stopped. A lost start/restart can leave an unknown job outcome. Use the app's job/status recovery, inspect History, and make an explicit new choice; do not repeatedly press Analyze expecting a free retry.

18. Configure optional API and local routes

  1. Open AI connections. Choose OpenAI API, Claude API, Gemini API, Local Ollama or Local compatible model server.
  2. Enter the exact model identifier available to that account/server. Declare supported image input and structured JSON output accurately. A checkbox/name is a declaration, not proof.
  3. For a local route, enter its port. Only literal 127.0.0.1 is used. For a compatible server, explicitly confirm the operator's local-execution declaration and its limitation.
  4. If the route needs a key, enter it in API key for this app session. Choose whether to enable the connection after its check.
  5. Save connection choices stores non-secret configuration locally. It does not run a model, share artwork or validate a licence.
  6. Under Current connections choose Check this connection with the PanelTide sample. Read the usage disclosure. Use Check connection progress to inspect this route's observed job without restarting inference.
  7. Return to Review workspace, prepare your own materials and select this route explicitly for Analyze.

Entered keys exist only in the current companion process session; they are not written to the choices file, recovery journals or exports. Restart requires re-entry unless an operator configured an environment credential. Status reports credential availability/storage, never its value. Ignore the existing session/environment key affects this running session; it does not revoke a key at the provider and an environment credential can be present on a later restart.

Save the current input before switching provider. Refresh saved choices refuses while edits are dirty, avoiding silent key/input discard. This form is not promised as a crash-durable draft. Every sample check can consume allowance or incur API charges. Exact price and remaining quota are unavailable. No automatic retry or provider fallback sends the same art elsewhere.

19. Read a recommendation critically

PartHow to use it

45. Worked example: a disputed balloon tail

Suppose the declared intent is that Mara says STOP and Elias is silent, but the supplied schematic balloon tail ends at Elias's head. Review one page first to check local attribution. Add the neighbouring page only if it helps establish who is speaking or the reaction.

  1. Supply the intent and accurate character positions; state that the drawing is schematic.
  2. Prepare the chosen scope and inspect sharing before Analyze.
  3. Check whether the observation matches the actual tail. A false observation should not become a task.
  4. Compare two options: move the balloon nearer Mara for a shorter tail, or keep symmetry and use a longer tail. Weigh crossing/clutter against composition.
  5. Read the citation: the tail convention supports associating speech with a speaker; it does not prove one coordinate is best.
  6. Keep neutral poses intentional if they serve the mood. A gesture is an optional experiment, not an obligatory realism correction.
  7. Make a task for the choice you accept, edit in your drawing app and review the exported revision.

If an unknown dark shape affects staging, add a scene note before requesting stronger advice. Missing context is a reason to qualify the judgment. Do not assume the model has read the next page, the complete script or a character bible you did not include.

46. A repeatable professional workflow

  1. Before a session: retain native masters and a checked work backup. Confirm comic identity, reading direction, intended audience and source rights.
  2. Separate planning from rendered art. Save story/script versions, propose/approve canon deliberately and map only confirmed artwork targets.
  3. Choose a concrete editorial question and the smallest useful review scope. Add neighbours for local transitions; state actual print spread/page-turn or scroll assumptions.
  4. Inspect the frozen sharing context and current provider readiness. Use an explicit sample check after route/model/config changes.
  5. Assess observations against supplied pixels, then general principles against their exact source locators. Record uncertainty and tradeoffs; preserve valid intentional choices.
  6. Make a task for accepted advice. Prepare an editable brief and isolated drawing-app candidate. For a supported text edit, use fresh native Read/Preview/Apply and inspect real fit.
  7. Export the actual revision and add it as explicit new material. Keep earlier page/review identity rather than pretending a completed checkbox validates new artwork.
  8. Re-review the revision with appropriate context. Compare through your own supplied evidence; automatic side-by-side acceptance/whole-issue synthesis is not implemented.
  9. Before delivery: check lettering at actual output size, technical print/export specs, source licences, sequence, proofreader/localization and accessibility outside unsupported assumptions.
  10. At session end: save valid work, wait for confirmed recovery copies, export necessary original/story files and make/download a checked backup.

For a 30-plus-page issue, label every subset and gap. Current page-review transport handles at most 10 selected images; the library cap is 30 pages/comic. Do not use a subset result to claim whole-issue editorial coverage or create copies to falsely merge review authority.

47. Before exporting for publication

  1. Inspect your editable master in the drawing app at the intended reading/print scale.
  2. Confirm dialogue, speaker attribution, reading direction and intentional exceptions with a human reading pass.
  3. Review revised material, not only the old recommendation or a completed task checkbox.
  4. Check output dimensions, color profile, bleed/safe areas and publisher-specific requirements in your actual production tools.
  5. Keep attribution/licence records for external assets and distinguish originals from generated or technically converted candidates.
  6. Archive masters plus appropriate source-only and full workspace backups.

A clean heuristic result, a valid citation ID or zero AI findings is not approval for publication. Those needs remain part of the roadmap and your production workflow.
